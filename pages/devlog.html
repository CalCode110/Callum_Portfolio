COMP710 · Semester Log

Dev Log

A week-by-week record of what I built, what broke, and what I learned.

01
Semester Kickoff

No Easing In

Week 1 was an immediate wake-up call. Most papers start slowly — COMP710 had work from day one. I had to get Visual Studio 2022 set up and start working with the game programming framework straight away. It set the tone for the whole semester: this class moves fast and expects you to keep up.

02
C++ Functions · UI Design

Tic-Tac-Toe

This workshop was focused on learning C++ functions in relation to simple UI game design. I built a small two-player Tic-Tac-Toe game using a basic console UI — getting comfortable with game loop structure, input handling, and win condition checking.

03
SDL2 · Sprites · Textures

Sprites and Rendering

This week was about getting images and sprites into the program for the first time. I implemented the base C++ code needed to manage textures, handle rendering, and control sprites within the game framework. There was a lot of troubleshooting — especially around texture loading paths and render order — but by the end I had a solid handle on how SDL2 handles drawing to the screen.

04
Git · Scenes · Space Invaders · FMOD

Git, Scenes, and Audio

A big week. Set up a Git repository — immediately the best quality-of-life change I'd made all semester. Implemented spinning sprite checkerboards, SceneCheckerBoards, and SceneBouncingBalls, each requiring troubleshooting around positioning, screen scaling, and border collisions.

Completed Space Invaders with a working game loop, then integrated FMOD audio and added an FMOD splash screen. Also prototyped a game home screen. Realised I'd missed some code from the lectures and had to go back and catch up — a good lesson in keeping pace with the weekly material.

05
Exemplar Viewing

Seeing the Standard

This week we looked at game pitches and examples of previous students' individual game projects. It was eye-opening — seeing the range of what people had built and the quality bar that had been set gave me a clear idea of what to aim for. It shifted my thinking from "get it working" to "make it something worth showing."

06
In-Class Review · Game Demo

First Progress Review

I presented my code and early ideas for the individual project to the class. At this stage it was still fairly rough — more of a direction than a finished concept — but I got useful feedback that helped shape where the project went from here. Having an external perspective early on was valuable; it highlighted a few assumptions I'd made about the design that needed rethinking.

07
Individual Project · Development

Building Rally Apex Hunter

Week 7 was heads-down development on the individual project. With the feedback from the Week 6 review in mind, I focused on getting the core gameplay loop of Rally Apex Hunter functioning — car movement, basic track boundaries, and the beginnings of the physics system. The submission deadline was approaching and there was still a lot to implement, so prioritisation became important.

08
Individual Submission · Group Intro

Submitting and Shifting Gears

Individual project submission week. Getting Rally Apex Hunter across the line required a final push — tying together the AI, audio, and documentation in the last stretch. After submission, I had a brief first meeting with the group for the upcoming team project. It was a good reset moment; switching from solo work to collaborative development required a different mindset entirely.

09
Group Project · Planning

Dungeon Descent Takes Shape

With the individual project submitted, the focus shifted entirely to the group project. This week was about aligning on the concept for Dungeon Descent — agreeing on the game direction, dividing responsibilities, and setting up our Scrum workflow. We got the product backlog started in MS Planner and began the first sprint. Having a clear structure early made the rest of the project run a lot smoother.

10
In-Class Review · Group Demo

Second Progress Review

The second in-class review was for the group project. We presented what we had so far and received feedback from the lecturer — the key message was that we needed to push further with the content and features. It was a useful checkpoint that made it clear we had more ground to cover than we'd originally planned, which motivated us to accelerate in the final weeks.

11
Group Project · Assets

Polishing and Sprite Work

This week I focused on polishing the visual side of Dungeon Descent. I spent a significant amount of time sourcing sprites that fit the aesthetic we were going for — finding assets that looked cohesive together is harder than it sounds. I refined and combined layers in Photopea to get everything consistent. Meanwhile the rest of the team was pushing on the core gameplay. Good division of labour this week.

12
Group Project · Final Push

Crunch Before Submission

The final week of active development before submission. Everything came together — bugfixes, final asset integration, documentation sign-off, and making sure the build actually ran cleanly. As with most projects, it came down to the wire, but we shipped a complete version we were genuinely proud of. The experience of managing a deadline as a team is different to solo work in ways you don't fully appreciate until you're in it.

13
Submission · Reflection

The Final Push

Final week — group project submitted, post-mortem written, and the personal portfolio (this site) pulled together. Cutting it fine on the portfolio was very on-brand for the semester. Looking back, COMP710 was the most demanding paper I've taken at AUT and easily the most rewarding. I went from building basic scenes and a Tic-Tac-Toe game in Week 2 to shipping a complete racing game with AI and spatial audio, contributing to a full group project, and building a portfolio website to show for it all. If I were starting again I'd manage my time more consistently week-to-week rather than letting things pile up — but honestly the pressure produced some of my best work.
